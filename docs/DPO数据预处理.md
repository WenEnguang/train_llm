## DPO的数据预处理
**根据在SFT阶段的踩坑和试错经验，DPO阶段的数据预处理主要包括以下几个方面：**
1. marker生成、空think剔除、完全复用SFT阶段的写法
2. `mask_dpo_mask`和SFT阶段的`mask_sft_mask`的区别：SFT输出`-100`/真实token_id这种labels，DPO输出`0/1`掩码。由于768的长度有限，可能会找不到`<im_end>`这类的标记，`mask`会一直标记到尾，而不是放弃这部分：截断只是丢了结尾一小段，前面被截断保留下来的内容依然是有效的训练信号，不该因为没找到结束符就把整段清零。
3. `process_one_side`里做了`next-token shift`：`x = input_ids[:-1]`，`y = input_ids[1:]`，mask 也同步右移对齐——DPO loss 原理标准做法，存储的序列长度是 `max_seq_len - 1`（也就是767），不是768。
4. 防御性检查：如果 chosen 或 rejected 任一边出现全零 mask（说明 marker 没匹配上），统计占比超过5%就直接 raise，不会让这种问题一路带到训练阶段才暴露成 loss 异常。
