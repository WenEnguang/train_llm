# DPO训练结果评估
### 验证集的loss（loss/val）
单调下降从500 -> 3000 -> 6000 -> 9000 -> 13000,损失值一直是单调下降的，并在13000步左右是趋于稳定的。可以确定本次的DPO训练是收敛的。
![[DPO_Loss_val.png]]
### 验证集reward的准确率（Reward/val_acc）
验证集上，policy认为chosen比rejected更优的比例：
50% 是完全随机瞎猜的基线（policy分不清chosen和rejected，跟扔硬币一样）。从66.3%起步、爬升到68.7%并稳定住，说明policy 确实学到了真实的偏好信号，而且这是在验证集（训练时没见过的数据）上测出来的，不是在训练数据上死记硬背的结果：证明学到的是可泛化的偏好倾向，而不是过拟合的问题。
但是目前的reward准确率仍然不够高，说明DPO阶段的训练还可以继续优化。但是限于目前的模型仅仅64M参数量，模型的容量有限，可能无法学习到更复杂的偏好信号。
![[DPO_Reward_val_acc.png]]
### SFT/DPO对比评估（暂不理想）
从结果上来看，SFT阶段产生的结果和DPO阶段产生的结果并没有发生太大的改变，接下来尝试：
- 放大学习率，目前的4e-8的学习过小，导致无法学习到有效的知识；
- 检查DPO数据集的质量，查看chosen和rejected的差异性是否足够明显，不然的话，就会导致DPO根本就学不到东西；
- 调整beta，beta越小，policy越偏离reference model。

第一步：先去调整学习率。将学习率调节的激进一些，4e-8 -> 5e-6；
第二步：再次检查DPO数据集的质量；
第三步：调整beta

### 数据调整
修改`core/train_dpo.sh`中参数，将`lr`从4e-8改为5e-6，beta从0.1改为0.3，重新训练DPO模型。得到的结果如下表：
| 指标 | 实验1（lr=4e-8,beta=0.1） | 实验2（lr=5e-6,beta=0.3） | 变化 | 
| --- | --- | --- | --- |
| loss/val(step=500) | 0.688 | 0.566 | 起点更低 |
| loss/val(step=13000) | 0.6214 | 0.3227 | 收敛更低，loss几乎减半 |
| Reward/val_acc(step=500) | 0.663 | 0.696 | 起点更高 |
| Reward/val_acc(step=13000) | 0.6887 | 0.87.13 | 收敛更高，reward准确率提升了约18个百分点 |

### 数据第一次调整之后结论
现在的结果输出看起来的结果比之前的输出结果“更好”，但是有问题就在于：
- 模型对于输出的结果错误的判断：之前是模型直接不回答或是模糊回答，但是目前的模型输出的结果是“自信满满”的错误回答，错的更加隐蔽、更加难以发现。
- 模型的多轮回答问题：模型的回答效果并没有发生很好的改善。

**目前的核心问题**：DPO并不会给模型注入新的知识，它只是让模型学会了如何更好地选择答案，而不是让模型学会新的知识。也就是说，DPO阶段的训练并没有让模型变得更聪明，只是让模型在面对同样的问题时，能够更好地选择答案。

**下一步计划**：先继续尝试调整DPO阶段的训练参数或者尝试使用训练阶段强度不同的ckpt模型
